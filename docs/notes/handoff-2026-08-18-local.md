## 2. RPA 経路 — 開通しました

前セッションで「新しいセッションなら通るはず」としていた件です。通りましたが、
**理由は前回の見立てとは違いました**。訂正しておきます。

### 効いた手順

1. **先にアプリを起動しておく**（ショートカットは不要でした）
2. `request_access` に **`RawInspector.exe`**（拡張子つきの exe 名）を渡す

前回は「スタートメニューに登録された名前でないと引けない」と書きましたが、
**起動中のプロセスなら exe のファイル名で引けます**。`Raw Inspector` や `RawInspector`
では引けず、`RawInspector.exe` で通りました（`didYouMean` が教えてくれます）。

つまり `%APPDATA%\...\Start Menu\Programs\Raw Inspector.lnk` は**なくても困りません**。
消しても構いませんし、置いたままでも害はありません。

### スクリーンショットは使えません（重要）

**computer-use の `screenshot` はこの WPF 窓を写しません。** 許可済み・最前面・
`SetWindowPos` で TOPMOST・`GetWindowDisplayAffinity` は 0（除外なし）、
それでも画面に出ません。3枚のモニタすべてで確認しました。原因は追っていません。

一方、**入力（`key` / `type` / `left_click`）は普通に効きます**。

### 回避策 — 観測は `PrintWindow` で行う

`PW_RENDERFULLCONTENT`（フラグ 2）で窓を直接 PNG へ焼けば、隠れていても正しく写ります。
子窓（ファイルダイアログや `ScopeWindow`）もプロセスIDで列挙すれば拾えます。

```powershell
[PW]::PrintWindow($hwnd, $hdc, 2)   # 2 = PW_RENDERFULLCONTENT
```

**「入力は computer-use、観測は PrintWindow」**の組み合わせで一通り操作できます。
実際、この手でフォルダを開き、`F7`・`F8` を押し、結果を読み取りました。

クリック座標が要る場合は、窓を既知の位置へ `SetWindowPos` してから
`(窓の左上 + 画像内座標) × (スクリーンショットの幅 / 画面の幅)` で出せます
（`PrintWindow` の画像は `GetWindowRect` と 1:1 で対応します）。

## 4. noise の生成画面が固まる件（修正しました）

生成画面でパターンに `noise` を選ぶと**アプリが固まります**。応答なしになり、
メモリが 5 秒で 1.3 GB ずつ増え続けます（16 GB を超えたところで手で落としました）。

### 原因

`PatternOptionRow.BuildPresets`（[`ViewModels/PatternOptionRow.cs`](../../apps/RawInspector/ViewModels/PatternOptionRow.cs)）の
「上限まで等間隔に刻む」ループが、**int の桁あふれで終わらなくなります**。

noise の `seed` だけ上限が `2**31 - 1` です。刻み幅は `ceil((上限-下限)/7)` なので
約 3 億。`v` が上限ちょうど（2147483647）に達したあと `v += stride` すると
int の範囲を越えて**負へ回り込み**、`v <= high` が永遠に成り立ちます。
毎周 `values.Add` するので、UIスレッドを握ったままメモリを食い続けます。

上限を持つ他のつまみは最大でも 1024 なので、**この経路に入るのは noise だけ**です。

これは `fd29dc0`（HEAD）にもある**前からの不具合**で、いま作業中の変更が
持ち込んだものではありません。PR #2 のブランチでも同じように固まります。

### 直し方

2つ入れました。

1. **上限が桁違いに大きいものは、上限が無いのと同じに扱う**（`WidestRangeWorthSpacing = 4096`）。
   仮に桁あふれしなくても、3 億刻みの数が 8 個並ぶだけで「これだろう」という値になりません。
   seed は上限無しと同じ扱いになり、`1, 2, 4, 5, 8, 10, 16, 20, 32, 64` が出ます。
2. **刻みを long で持つ**。等間隔のループと 2 の階乗のループの両方です。
   1 の閾値で今は届きませんが、桁あふれで無限ループになる形自体を残さないためです
   （2 の階乗の側も、上限が 2^30 なら同じように回り続けます）。

閾値 4096 は、いまカタログにある本物の上限（最大 1024）をすべて含みます。
**noise 以外のつまみの見え方は変わりません**（siemens の `4,107,…,720`、
colormatrix の `2,4,8,16` が変わらないことを実機で確認しました）。

### まだ無いもの

C# 側にテストの置き場がありません。`BuildPresets` は入出力だけの静的メソッドなので、
テスト計画（§3）を始めるなら**最初の1件にちょうどいい**題材です。
