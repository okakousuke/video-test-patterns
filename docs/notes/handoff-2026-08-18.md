## 3. 未検証（最重要）

**Windows での WPF ビルドが通っていません。** これが唯一の残作業です。

```powershell
dotnet build .\apps\RawInspector\RawInspector.csproj
```

理由は環境で、Ubuntu の .NET SDK には WindowsDesktop SDK が同梱されておらず、
Microsoft 配布版はプロキシで遮断されていました。代わりにやったこと。

- コードビハインド以外の C# を、**本物の WPF 参照アセンブリ**（NuGet の
  `Microsoft.WindowsDesktop.App.Ref`）に対してコンパイル → 成功
- XAML は整形式チェックと、`{Binding}` 名・`{StaticResource}` キーの実在チェック → 0件

**XAML のビルドと実行だけが未確認**です。ローカル（Windows）なら普通に建つはずなので、
この回避策は再現しなくて構いません。ビルドエラーが出たら XAML 側の可能性が高いです。

### B. ドットバイドット（PC 版）

**等倍（100%）が物理ドット等倍ではありません。** Windows の表示スケーリングが 150% なら
1画素が 1.5 物理ドットになります。全画面でも同じです。詳細は
[`signal-source.md`](signal-source.md) と `docs/usage/viewer.md` に書きました。

やること。

1. `VisualTreeHelper.GetDpi(this).DpiScaleX` を読み、倍率表示を実効値にする
   （`100 %（1画素 = 1.5ドット）`）
2. 「ドットバイドット」ボタン（GIMP と同じ考え方）。`ScalePercent = 100 / dpiScale`
3. 非整数倍のときは絵の上に警告（既存の縮小警告と同じ仕組み）
   「1画素の縞が1ドットと2ドットに化けます」

### C. 外周の線を影にする

いまは 1 DIP の実線（`MainWindow.xaml` の `PreviewFrame`、`#FF6E7480`）で、
**1ドットの縁のように見えます**。Photoshop は Canvas Border を環境設定にして
Line / Drop Shadow を選ばせています。影なら画素と混同しません。

### D. `csproj` の `ApplicationHighDpiMode`

`ApplicationHighDpiMode=PerMonitorV2` は WinForms 用のプロパティで、WPF では効かないはずです
（一次資料は確認できていません。learn.microsoft.com がプロキシで遮断されていました）。
WPF (.NET Core) は既定で PerMonitorV2 なので実害はありませんが、
**「DPI 対応済み」と読める記述が残っている**のは確認したほうがよいです。

### E. manifest v2（wire 語彙 ＋ タイミング）

FPGA へ行く前に決めるべき契約です。方針は [`signal-source.md`](signal-source.md) に。
**RTL を書き始めてから決めると、両側を同時に直すことになります。**
