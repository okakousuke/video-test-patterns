# 信号源として名乗れるか（設計メモ）

`apps/RawInspector` の全画面表示を「モニタ評価に使える信号」と言えるか、という議論の記録です。
結論と、その根拠になった数字を残します。**同じ調査をやり直さないための memo** であって、
仕様書ではありません。

## 結論

| | 名乗るか | 理由 |
| --- | --- | --- |
| 標準信号源 | **名乗らない** | ケーブルに出る値をアプリが決められない |
| ドットバイドット表示 | **アプリ層でのみ保証する** | 解像度だけを対象にする。色は保証しない |
| モニタ評価に使えるパターン表示器 | **条件付きで可** | 「何かしている」の検出はできる。「規格適合」の証明はできない |

## PC 版が信号源になれない理由

アプリが作った RGB888 が、そのままケーブルへ出るとは限りません。間に3層あります。

| 層 | 値を変えうるもの |
| --- | --- |
| OS | Windows 11 の Advanced Color / 自動カラー管理。SDR を HDR 合成空間でエミュレートする |
| GPU ドライバ | 出力の RGB / YCbCr、Full / Limited レンジ、GPU スケーリング、画質補正 |
| モニタ | シャープネス、オーバードライブ、内部スケーラ、ダイナミックコントラスト |

そして**アプリ自身ではこれを検証できません**。PC ベースのパターン発生は業界にも実在しますが
（Calman の VirtualForge など）、「ファイルは正確でも、ビデオカードが正しく出しているか
確認できない」ことが弱点として知られています。

### 等倍が物理ドット等倍でない件

WPF の `Image.Width` は DIP（1/96インチ）なので、Windows の表示スケーリングが 150% なら
**等倍（100%）でも1画素が 1.5 物理ドット**になります。全画面にしても変わりません。
非整数倍のときは、最近傍のため1画素の縞が1ドットと2ドットに化けます。

GIMP はこれを "**Dot for Dot**" という明示的なモードとして持っています。
「等倍」の意味が環境で変わることを、UI の一級概念として扱う、という先例です。

### 10bit が出せない件

いまの実装は BGRA32（8bit）で、WPF の合成も 8bit です。10bit を出すには
D3D11/12 の 10bit スワップチェーン＋排他フルスクリーンが要り、**WPF では届きません**。
v210 / P010 / MIPI10 の 10bit RAW を持っているのに 8bit で出すのでは、
バンディング評価という一番の用途が成立しません。

## それでも実用になる範囲

ドットバイドットさえ実現すれば、**「モニタが何かしていること」の検出**はできます。

| できること | 使うパターン |
| --- | --- |
| ドット欠け・ムラ・色ムラ | 一様面（raster） |
| バンディング・階調飛び | ランプ |
| 内部スケーラが噛んでいる検出 | 1画素縞（hatch / linepairs） |
| シャープネス補正が 0 でない検出 | 1画素縞にリンギングが出る |
| 4:2:2 / 4:2:0 で受けている疑いの検出 | 赤青1画素縞（`hatch_redblue`）が滲む |

**「規格に適合している」証明ではありません。** この区別が名乗り方の分かれ目です。

## では何があれば名乗れるか（FPGA 案）

RAW と manifest を FPGA ボードへ渡し、そこで信号を生成する。PC に無いものを FPGA が持ちます。

1. **タイミングが自分のもの**になる（いまの manifest に無い部分）
2. **ビット完全**。OS 合成も ICC も GPU スケーラも挟まらない
3. **YCbCr をそのまま線に出せる**。4:2:2 でモニタに渡して処理を試せる
4. **InfoFrame を意図的に間違えられる**。「full と申告して limited を流す」事故を再現できる

### 転送はストリーミングしない

これが構成の成否を分けます。

- 1080p60 非圧縮 = **373 MB/s**。USB 2.0 でも GbE でも流しきれない
- しかし**静止パターンは流す必要がない**。1枚を DDR に置いて VDMA でループさせる
- FHD 1枚 = 6.2 MB。GbE で 0.06 秒、100Mbps でも 0.5 秒
- Mizar Z7（7020版）の DDR3 は 1GB。**FHD 約160枚 / 720p 約360枚**が常駐できる

**ここをストリーミング前提で設計すると破綻します。**

### 帯域の天井（HDMI / TMDS）

| モード | TMDS レート（1レーン） | 7-series HR バンクでの見通し |
| --- | --- | --- |
| 720p60 8bit | 743 Mbps | 余裕 |
| **720p60 10bit** | **928 Mbps** | **余裕**（deep color の入口として最適） |
| 1080p60 8bit | 1,485 Mbps | 定格超えだが実例多数。-2 グレードは有利 |
| 1080p60 10bit | 1,856 Mbps | 厳しい |
| 4K | HDMI 2.0 必須 | 7020 では不可 |

deep color は `bpp/24` 倍のクロックになります（10bit で +25%）。
**720p60/10bit は 1080p60/8bit より軽い**、というのが効きます。

HDMI 1.4 に **4:2:0 はありません**（HDMI 2.0 から）。42形式のうち 4:2:0 系は線に出せません。

### ボードの比較

| | Mizar Z7（所有） | XPE_ZU100 + XME0803 | PZ-A735T-KFB |
| --- | --- | --- | --- |
| デバイス | XC7Z020-**2**CLG400 | ZU3EG / ZU4EV | XC7A35T-2（**PS なし**） |
| 価格 | 約 ¥3万 | 約 ¥14万（4EV 見積り） | 安価 |
| 出力 | HDMI ×2（**両方 in/out 可**） | HDMI TX 1080p ＋ **Mini DP** | HDMI（要確認） |
| DP | — | **PS の BANK505 MGT 直結、4K30 / 1080p60** | — |
| 深度 | 自作 GCP で 10bit | **10 / 12bit がハードで** | 自作 |
| 4:2:0 を線へ | 不可 | **可** | 不可 |
| DDR | 1GB（7020版） | SoM 依存 | 1GB |
| **ループバック自己検証** | **可**（HDMI2 を RX に） | HDMI 側のみ。**DP に入力は無い** | 不可 |

**Mizar Z7 の HDMI は直 TMDS**です（リファレンスの接続図で確認：BANK35 から
CLK_P/N・DATA0/1/2_P/N がコネクタへ直結、I2C(DDC) と HPD も FPGA へ）。
送信チップが無いので、**GCP も含めて自分で書けます。HDMI TX Subsystem IP（有償）は不要**です。

AMD の HDMI 1.4/2.0 TX Subsystem は Vivado 同梱ですが、全機能にはライセンス購入が必要で、
評価版は一度きりの60日です。**ZU+ で DP を選べばこの出費は不要**になります
（PS の DisplayPort は 4K30 / Y-only・444・422・420 / 6・8・10・12 bpc）。

XPE_ZU100 の対応表では **Mini DP は 3EG でも 4EV でも ✔️**。違いは実質 PCIe 3.0 x2 の有無です。
パターン発生器に PCIe は要らないので、**3EG で見積もり直す価値があります**。

### PS の無いボードを避ける理由

Artix-7 が安いのは PS が無いからで、そこが削られると DDR 制御（MIG）・Ethernet 受信
（MicroBlaze + lwIP）・起動が全部自作になります。**削られている部分がこの企画の中核**です。
PCIe が欲しくなった理由（帯域）も、プリロード方式を選んだ時点で消えています。

## 段取り

| 段 | 内容 | 追加投資 |
| --- | --- | --- |
| 0 | PC 側に送出用エクスポート＋ manifest v2 設計（FPGA 不要） | ¥0 |
| 1 | Mizar Z7 で 720p60 **8bit** 1枚表示。転送＋DDRプリロード | ¥0 |
| 2 | **HDMI2 でループバック受信 → 比較窓で最大差 0 を確認** | ¥0 |
| 3 | 720p60 **10bit**（GCP ＋ クロック 1.25 倍） | ¥0 |
| 4 | 1080p60 8bit（帯域の限界） | ¥0 |
| 5 | ZU+ の **PS DP** で 4K30 / 10-12bit / 4:2:0 | 約 ¥14万 |

**段3の前に段2を置くのが肝**です。deep color は「出ているつもり」がいちばん危ないので、
検証系を先に持つ。段2があれば、段3は「10bit にして差が 0 のままか」を見るだけになります。

ループバックが効くのは、**安いキャプチャが使えない**ためでもあります。USB の UVC キャプチャは
YUV 4:2:2 へ変換して出すものが大半で、ビット完全の検証には使えません。

## manifest v2 で決めること

信号を出す側になる以上、いまの manifest に無いものが要ります。

- **タイミング** — 画素クロック・h/v total・同期幅と極性、または DMT/CVT のモード名
- **線に流す形（wire）** — `storage`（planar / v210 / MIPI10）は**ファイルの詰め方**であって、
  線に出る形ではありません。HDMI に v210 は流れません。両者を混ぜると、
  「v210 を出力した」という言えないことを言い始めます

**wire の語彙は DP の集合（Y-only / 444 / 422 / 420 × 6/8/10/12 bpc）で定義**しておくと、
HDMI はその部分集合として表現できます。出口が変わっても契約を作り直さずに済みます。

`matrix` / `range` / `subsampling` / `bit_depth` は AVI InfoFrame の中身そのものなので、
すでに持っている情報がそのまま線の申告に使えます。
