# パターンを作る

ツールバーの「＋ 生成…」、または[ホーム画面](launcher.md)の「パターンを作る」で開きます。
条件を選んで生成すると、できたRAWをそのまま一覧へ取り込んで選択します。
**作る→すぐ見るが1周します。**

## 画素を作るのはPython側です

このアプリは生成しません。`python -m vtp` を呼ぶだけです。
C#側にも生成を書くと、同じ仕様の実装が2つになり、片方だけ直したときに黙ってずれます。
検証の土台そのものが崩れるので、実装は1つに保っています。

繋がっていないときは窓の上に黄色い帯が出て、何も選べません。
対処は[ホーム画面](launcher.md#生成器の状態)の説明を見てください。

## 手順

窓は上から順に4つに分かれています。

### 1. 何を描くか

パターンとサイズを選びます。パターンが何を見るための絵かは、本体側の一覧の下に出ます。

### 2. どう格納するか

| 項目 | 内容 |
| --- | --- |
| 色モデル | `rgb` か `ycbcr` |
| 色差 | `4:4:4` / `4:2:2` / `4:2:0`。`rgb` では `4:4:4` のみです |
| ビット深度 | 8 か 10 |
| 格納形式 | `planar` / `packed` / `nv12` / `p010` / `v210` / `mipi10` |
| range | `full` か `limited`（放送系の制限範囲。8bitで黒16・白235） |
| matrix | `bt601` / `bt709` / `bt2020` |
| 10bitの詰め | 16bitコンテナへ10bitを入れるときの寄せ方です。8bitでは使いません |

各項目の意味は[格納形式](../formats.md)にあります。

### 3. このパターンの設定

パターンごとのつまみです。**空欄は「触っていない」という意味**で、
触った項目だけがコマンドに載ります。「既定へ戻す」で全部空に戻せます。

並びも説明も生成器から来ます。この画面に表は持っていません。

### 4. どこへ出すか

フォルダとファイル名を指定します。ファイル名を空にすると条件から名前を作ります。
**拡張子は生成器が付けます。** 1回の生成で3つできます。

| ファイル | 内容 |
| --- | --- |
| `*.raw` | 画素のバイト列 |
| `*.manifest.json` | 寸法・色形式・格納形式などの生成条件 |
| `*.preview.png` | 生成器が出した確認用のPNG |

最後に「生成」を押します。

## 成立しない組み合わせ

選択肢は黙って減らしません。減らすと、なぜ消えたのかが分からないためです。
選べるままにして、成立しない理由と、次に何を変えればよいかを赤い枠に出します。

```text
この組み合わせは成立しません。nv12 で使えるのは 色モデル ycbcr、色差 4:2:0、8bit、… です。
この条件では幅が 6 の倍数、高さが 1 の倍数である必要があります（指定: 1921 x 1080）。
近い値は 1920 x 1080 です。
```

生成器が断ったときの文面は、こちらで言い換えずにそのまま出します。
言い換えると、生成器が実際に何を嫌がったのかが分からなくなるためです。

## 実行するコマンドは隠しません

窓の下に、いま実行される予定のコマンドがそのまま出ています。
「コマンドをコピー」で端末へ貼れば、同じものを手で再現できます。

## 選べる条件はどこから来るか

「v210 は幅が6の倍数」「p010 は上位詰めのみ」といった規則をC#側へ書き写すと、
生成器を直したときにずれます。ずれ方は「GUIでは作れるのに生成器が弾く」か、その逆で、
どちらも原因を探しにくい形で出ます。

そこで生成器の申告をそのまま使っています。

```sh
python -m vtp --describe
```

この表は規則を書き出したものではなく、生成器側の `validate()` を実際に通して作られています。
幅・高さの倍数も、通る最小の値を探して求めています。

呼び出すコマンドは窓のいちばん下の「生成器の呼び出し方」欄で変えられます（既定は `python -m vtp`）。
仮想環境のPythonを名指ししたいときなどに使ってください。変えたら「接続し直す」を押します。

## まとめて作りたいとき

この窓は1回に1本です。パターンを一通り並べる、条件を振って量産する、といった用途は
[スクリプトを走らせる](batch-tools.md)のほうです。
