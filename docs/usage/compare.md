# 2枚を突き合わせる

ツールバーの **「⇔ 比較…」**（`F8`）で開きます。RAWを1本選んでいると押せます。

並べて見るだけでは「同じに見える」までしか言えません。
**1コード値の差は目で見えませんし、見えないからといって無いわけでもありません。**
差は目で見るものではなく、数えるものです。

## 左と右

| | 何を | どう読むか |
| --- | --- | --- |
| 左 | 本体でいま見ているRAW | **本体でいま使っている表示条件**（matrix・range・色差の戻し方・段） |
| 右 | 選んだ相手 | **manifest の記録どおり** |

右まで条件を変えられるようにはしていません。両方を触れると、出てきた差が
**どちらの条件のせいなのか言えなくなります。**

相手として選べるのは2種類です。

1. **同じRAW（manifest の記録どおりに読んだもの）** — いま条件を変えて見ているとき、
   その変更がどれだけの差になっているのかを数えられます
2. **開いているフォルダにある、同じ大きさの別のRAW** — 同じ絵を別の格納形式で持ったものどうしなど

## 大きさが違うものは比べません

拡大縮小して揃えることもしません。**揃えた時点で、画素は元のどちらとも違う値になります。**
「合わせて比べた差」は、どちらのRAWの性質でもありません。

そのため、相手の一覧には**同じ大きさのものだけ**が並びます。
選べるのに必ず断られる項目を並べても、断りを読むまで理由が分かりません。

## 何で比べるか

| 比べる値 | 何が分かるか | 使える条件 |
| --- | --- | --- |
| 表示RGB（0-255） | **見え方**の差。8bit へ変換したあとの値どうし | 大きさが同じなら常に |
| コード値（0-255 / 0-1023） | **データ**の差。RAWから読んだ生の値どうし | ビット深度と成分の意味が同じとき |

コード値で比べられない組み合わせでは、そのボタンが押せなくなり、理由が出ます。

- **ビット深度が違う** — 8bit の 235 と 10bit の 940 の差 705 には意味がありません
- **成分の意味が違う** — Y' と R を引き算しても意味がありません

どちらの場合も、見え方の差なら表示RGBで比べられます（どちらも8bitへ揃えたあとの値です）。

色差が間引かれている形式のコード値は、**戻したあとの値**で比べます。
戻し方（最近傍／バイリニア）は左右それぞれの条件に従います。

## 差の絵

成分ごとの差を R・G・B の位置へ置いています。赤いところは1つ目の成分だけがずれている、という読み方です。

**倍率を掛けないと、たいていの差は真っ黒です。** 1コード値の差は 1/255 の明るさなので、
そのまま出せば黒と見分けが付きません。既定は8倍で、1〜64倍から選べます。

倍率は絵の隣に出し続けます。掛けたことを忘れると、8倍した差を「これだけずれている」と読みます。

**真っ黒な差の絵は、それだけでは「一致した」の証拠になりません**（倍率が足りないだけかもしれません）。
一致したかどうかは、上の帯と下の数値で確かめてください。1バイトも違わないときは緑の帯ではっきり出ます。

## 数値

| 欄 | 何が分かるか |
| --- | --- |
| 最大差 | いちばん大きかった差 |
| 平均差 | 全画素の平均。全体がじわっとずれているのか、一部だけかの見当が付きます |
| 差のある画素 | 差が 0 でない画素の数と割合。**最大差だけでは、1画素なのか全面なのかが分かりません** |
| 最大差の座標 | そこが分かれば、本体で拡大して見に行けます |

## 読み方の例

- **格納形式だけが違う2本** — コード値の最大差が 0 なら、詰め方を変えても値は失われていません。
  `samples/raw` の10通り（planar / packed / NV12 / P010 / v210 / MIPI10）はすべて 0 です
- **同じRAWを matrix 違いで** — 相手に「同じRAW（manifest の記録どおり）」を選び、
  本体で matrix を変えます。取り違えたときの色ずれが何コード値ぶんなのかを数えられます
- **4:4:4 と 4:2:0** — 一様な面のパターンでは差が 0 になります（色差の細かい変化が無いためです）。
  差が出るなら、それは間引きの損失ではなく別の原因です
